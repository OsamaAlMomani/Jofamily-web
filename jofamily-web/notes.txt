RTC Notes — MediaStreamConstraints (Jan 15, 2026)

Question:
Explain this function/object:

const constraints: MediaStreamConstraints = {
  audio: false,
  video: selectedCameraId
    ? { deviceId: { exact: selectedCameraId } }
    : true,
};

Meaning:
- This is NOT a “function”; it is a JavaScript object that matches the TypeScript type `MediaStreamConstraints`.
- It is passed to `navigator.mediaDevices.getUserMedia(constraints)` to request camera/mic tracks.

Type shape (simplified):
- MediaStreamConstraints
  - audio?: boolean | MediaTrackConstraints
  - video?: boolean | MediaTrackConstraints

Fields:
1) audio: false
- Do not request microphone.
- Result: no mic permission prompt, and the returned MediaStream has 0 audio tracks.

2) video: ...
- The `video` field can be:
  - true  → “I want video, pick the default camera”
  - false → “I don’t want video”
  - an object (MediaTrackConstraints) → “I want video with specific requirements”

Your code uses a ternary (condition ? A : B):
- If `selectedCameraId` is set (user chose a camera):
  video = { deviceId: { exact: selectedCameraId } }
  Meaning: “Use exactly this camera device.”
  If that device isn’t available, getUserMedia may fail (often OverconstrainedError).

- If `selectedCameraId` is empty:
  video = true
  Meaning: “Use the default camera.”
  The browser/OS decides the default; on Windows this might be a phone-as-webcam if enabled.

Why `exact` matters:
- exact = hard requirement (must match or fail)
- ideal = soft preference (try to match, but can fallback)

Debug tips:
- After getUserMedia succeeds, check:
  stream.getVideoTracks()[0].label
  This usually reveals which physical camera you are using (PC webcam vs phone-as-webcam).
